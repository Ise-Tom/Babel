# P01-02 — Native stable identity and schema primitives

The original P01-02 primitive criterion is exercised in
`babel-synthetic-directory-v1`. [Phase 1 criterion](../phases/phase-01.md) ·
[P00-02 design](p00-02.md) · [ADR 0005](../adr/0005-directory-and-replication-invariants.md)

## Executable profile

The [workspace library](../../native/babel-directory/src/lib.rs) exports
`Directory::new`, `create`, `lookup_dn`, `lookup_guid`, `lookup_sid`,
`lookup_equal` and `rename`. Callers get immutable entry views and typed
identifiers. Each bounded in-memory instance allocates a synthetic domain SID,
then assigns monotonic RIDs beginning at 1000 and UUIDv4 GUIDs as entries are
created. The domain SID and GUID entropy come from the operating system through
the already locked `getrandom` 0.4.3. A failed allocation publishes neither
identity nor locator and leaves the next RID available. The profile contains
at most 1,024 entries. [UUIDv4 layout](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.4) ·
[Entropy API](https://docs.rs/getrandom/0.4.3/getrandom/fn.fill.html)

The only naming context is `DC=babel,DC=test`. Each object has one direct
`CN` RDN. The CN is 1–64 bytes, starts and ends with an ASCII letter or digit,
and may contain letters, digits, spaces, hyphens and underscores in between.
Input attribute labels and the naming context are ASCII case-insensitive.
The core keeps the CN's display spelling and indexes its lowercase key.
An ordinary rename may change the key or display case. A successful rename
updates the CN and DN locator while preserving the same GUID, SID, object
class and other attributes.

| Class | Required attributes besides the CN | Optional attributes |
| --- | --- | --- |
| `user` | `displayName`, `uidNumber` | `description` |
| `computer` | `dnsHostName` | `description` |
| `group` | None | `description` |

| Field | Syntax in this profile | Equality rule |
| --- | --- | --- |
| `cn` | The RDN value above | `ascii-case-ignore` |
| `displayName` | 1–64 printable ASCII bytes | `ascii-case-ignore` |
| `dnsHostName` | Up to 253 ASCII bytes with valid DNS labels and at least one label below `babel.test` | `ascii-case-ignore` |
| `description` | 1–128 printable ASCII bytes | `ascii-exact` |
| `uidNumber` | Canonical unsigned decimal `u32`, including `0` and without signs or leading zeroes | `unsigned-integer` |

Case-insensitive equality changes only ASCII letter case and retains whitespace.
Creation validates each class's required and allowed fields and precomputes
comparison keys using the same rules as lookup assertions. The core rejects
unknown, duplicate, wrong-class and server-managed input attributes. The
equality API rejects unsupported or mismatched rules and invalid assertion
values. LDAP matching OIDs and Unicode normalization require a broader profile.

## Original criterion and evidence

| Criterion | Executed check |
| --- | --- |
| Create stable identities | The public API creates a user, computer and group and resolves each through GUID and SID. The tests check distinct UUIDv4 values, a shared domain SID and increasing RIDs. |
| Rename preserves GUID and SID | Rename through the public API changes both the DN lookup and CN equality result. Name lookup releases the old key. GUID and SID lookups return the same entry, and a case-only rename preserves its canonical key. |
| DN collision protection | A case-equivalent destination collision leaves both objects, their values and their name, GUID and SID lookups intact. Duplicate creation leaves the existing occupant. Malformed names, a foreign identifier and a foreign naming context also fail through the public API. |
| Invalid schema and matching | Table-driven public API tests check unknown and missing classes/fields, syntax errors, reserved fields and unsupported or wrong-field matchers. An invalid creation leaves the name and RID available. |
| Failed mutation boundaries | The public capacity test checks that failure leaves the last entry and indexes intact and that rename still works at capacity. A private unit test injects GUID allocation failure and collision before the same insertion routine. |

Seven integration tests call the exported API from a separate Rust test crate.
One unit test covers the allocation faults. The local run used the pinned Rust
1.100.0 compiler on x86-64 Ubuntu under WSL2. The tests passed in debug and
release at source `03bc34e4a684314442d1c49c6f7e6ce20d5d0f90`. The directory
crate recorded 93.96% line coverage in the local instrumented run. Required
CI runs the workspace debug tests, runs both the directory and LDAP release
tests, checks the directory library's 90% line coverage threshold and retains
`directory-core-coverage.lcov` in the native evidence artifact. The independent
RootDSE smoke stays in the same required native workflow.
[Public API tests](../../native/babel-directory/tests/synthetic_profile.rs) ·
[Native CI](../../.github/workflows/native.yml)

Run these commands from the repository root to exercise the public API and the separate LDAP listener.

```sh
cargo test --locked -p babel-directory --test synthetic_profile
cargo test --locked --release -p babel-directory --all-targets
cargo build --locked --release -p babel-ldap
python native/babel-ldap/tests/smoke_ldap.py target/release/babel-ldap
```

Install the repository's hash-locked Python tooling before running the LDAP
smoke. That probe checks the existing listener independently from the directory
tests. [Python tooling](../../README.md)

## Acceptance scope

criterion in the declared profile on 22 November 2026.
[Dashboard decision](../../dashboard/progress.json) · [Pinned reviewed packet](https://github.com/Ise-Tom/Babel/blob/d3d8b291823f1831583e5f94323cf9a21f673028/docs/validation/p01-02.md) General LDAP DN/schema and

allocation still need their applicable implementations and qualification.

group authorization belong to P01-11. Network writes, credentials and real
client conformance remain separate work. The RootDSE listener stays read-only.
