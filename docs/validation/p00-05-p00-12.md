Run from a Windows PowerShell prompt on a prospective Hyper-V host with Python
3.12 or newer. The default storage root is the current directory. If lab disks
will live on a different volume, pass its existing local directory.

~~~powershell
python scripts/preflight_reference_lab.py
python scripts/preflight_reference_lab.py --storage-root D:\LabDisks --media D:\LabMedia\approved.toml
~~~

The observed run exited 2 with hypervisor inventory unavailable, memory and disk
shortfalls, and six missing media entries. Both cycles reported unrun. The check
reads Windows and Hyper-V inventory and hashes explicitly supplied media. It
reports only host platform/capacity, resource counts and per-role statuses.
It excludes identities, machine or switch names, credentials, media paths and
private rights record identifiers. Exit 0 means the supplied inputs are ready
for provisioning review. It does not establish privileges to create VMs,
network isolation, entitlement validity or a booted guest's configuration.
The required Python CI uses mocked inventory and project-owned synthetic bytes.

The optional TOML is a private, operator-reviewed input. Use ordinary local
files on a fixed disk and keep the manifest outside version control. Provide one
table per planned guest ID, all six for a complete preflight. Here is one
synthetic example showing the format. The private evidence identified by
rights_record must cover the exact file and offline installation/run on the
selected host. If the permission expires, set expires_on to the first date
the asset may no longer be used, in UTC. Keep staged update packages and their
digests and rights in the private installation inventory. Record actual guest
builds and installed packages after boot.

~~~toml
[reference-dc]
id = "synthetic-example-only"
path = "example-local-image.iso"
edition = "Windows Server 2025 Standard Server Core"
architecture = "x86_64"
build = "10.0.26100.33822"
~~~
