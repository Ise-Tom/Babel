# P00-15 — Storage driver and transaction qualification

Disposition: **technical exit criteria complete; owner validation requested**.
This packet covers the entire Phase 0 P00-15 gate, whose unchanged requirement is:

> Qualify the storage driver and transactional interface. Review versions,
> parameterization, cancellation, commit/error mapping and recovery before
> credentials or stable formats persist.

The selected implementation stack is **tokio-postgres 0.7.18 / Tokio 1.54.1**,
with PostgreSQL 18 (qualified image: 18.7, immutable digest in the Docker manifest).
The qualified deployment profile is a local Linux Unix socket, managed SCRAM role,
explicit durable database settings and individually owned connections with **no
connection pool**. This replaces the earlier candidate-only disposition. Changes
to stack, features, transport, pooling or relevant semantics require requalification.

## Exit-criterion disposition

| Criterion | Completed evidence | Passing-case identifiers |
| --- | --- | --- |
| Versions, features and maintenance | Exact direct pins and Cargo.lock, minimal features, upstream/alternative/unsafe review in ADR 0007; daily advisory/license/source audits; actual notice inventory retained | Required native audit; `scram_authentication_and_least_privilege_are_real`; `unsafe_session_durability_is_rejected` |
| Parameterization and interface | Default API accepts bounded typed create/rename operations. UUID text, fixed fixture SID, label and expected version are bound values. Generic SQL/transaction entry is available only with the qualification feature. No endpoint accepts SQL | `typed_input_limits_reject_before_any_database_request`; `parameter_binding_handles_literals_null_and_binary_without_sql_execution`; `typed_mutations_bind_identity_payload_and_reauthorize_receipt_replay` |
| Bounds | Streaming result collection caps 128 rows, 32 columns and 65,536 retained field bytes; statements cap 4,096 bytes and 32 parameters. Normal typed requests have smaller fixed bounds. Over-budget connections are discarded | `bounded_results_discard_over_budget_sessions`; `statement_and_parameter_budgets_are_enforced_before_execution` |
| Cancellation | Two-second connection and 600-ms operation deadlines; 300/100-ms default server statement/lock timeouts. Armed guards poison/close a connection if an in-flight query, BEGIN, mutation, rollback or COMMIT future is dropped. Uncertain sessions cannot be reused | Caller-dropped query/begin/rollback/mutation/commit cases; explicit cancellation and server/client/transaction timeout cases |
| Commit and errors | State, journal, audit intent and actor/request/payload receipt commit together. A caught statement error cannot become a successful COMMIT acknowledgment. SQLSTATE categories are redacted; unconfirmed commit returns UnknownCommit and never retries automatically | `caught_statement_failure_never_becomes_successful_commit`; `deferred_commit_failure_never_acknowledges_success`; serialization/lock/denial and raw-driver comparison cases |
| Lost durable reply | A private fault relay withholds the actual server COMMIT response. An independent connection first observes committed state/journal/audit/receipt. Connection loss or dropped caller then requires receipt recovery, with exactly one effect after retry | `durable_commit_with_lost_reply_is_recovered_without_repeating_mutation`; `dropped_commit_future_after_durability_requires_receipt_recovery` |
| Retry and authority | Transactional writer ordering serializes concurrent identical requests. Identical retries return the durable result; changed payload is denied. The fixture actor-active check occurs before receipt lookup, including after revocation | `concurrent_identical_requests_commit_once_and_conflicting_reuse_is_denied`; `typed_mutations_bind_identity_payload_and_reauthorize_receipt_replay` |
| Recovery before stable/credential formats | The harness actually SIGKILLs and restarts its owned database before commit and after confirmed commit. The first leaves no partial state; the second preserves the acknowledged receipt and permits a fresh write. Both mandatory checkpoints are independently coordinated by the Python controller | `driver_recovery_before_commit`; `driver_recovery_after_confirmed_commit` |

All declared scenarios must execute successfully with none missing, duplicated or
ignored. The harness fails if either real crash checkpoint is missing, even if
the Rust test command exits successfully. Required CI separately enforces at
least 90% driver-library line coverage and retains the source-bound scenario,
PostgreSQL/version/isolation/cleanup report, LCOV and dependency notice manifest.
The PR's CI run is the review-time evidence; the dashboard work record pins the
implementation and this packet. Tests, fixture and harness are linked below.

## Interface and trust reviewed

The typed path uses the existing atomic SQL state contract from ADR 0003/0004;
it no longer acknowledges a raw SQL command as a completed mutation. The normal
API has no generic SQL transaction entry point. There is no pool whose unknown
transactions could be checked back in. Receipt keys bind actor and request to
exact bounded payload equality, not an invented digest or cryptographic format.

The owned PostgreSQL service is part of the local trusted computing base.
SCRAM is enforced by the managed fixture's HBA rule and verified by denied
passwordless/wrong-password connections. The upstream driver also implements
legacy authentication; this profile does not authorize those methods or remote
TCP. Hostile-server protocol allocation and cryptographic CPU bounds are not
promised by the application row/field-retention limits. The relay parser is a
bounded test fixture, never part of the server or client library's runtime path.

The Rust driver's native/unsafe dependencies and actual license terms remain
reviewed as described in ADR 0007; this is not a memory-safety or independent
production security certification. The SHA-pinned backend image and source lock
must be retained with evidence. Pooling, remote TLS, other server versions or
platforms are new profiles and require their own evidence before use.

These remain release blockers at their actual implementation/qualification gates;
they are not silently removed, nor used to keep the completed P00-15 review open:

| Requirement | Remaining product work |
| --- | --- |
| P00-02 / P00-03 | Review the actual AD identity/schema/authorization and replication/restore contracts; do not freeze AD formats from these fixture tables |
| P00-12 | Qualify exact production OS/client builds; this driver run is Linux-hosted fixture evidence |
| P01-02 / P01-11 | Native GUID/SID/schema/matching and ordered ACL/inheritance/group authorization; the fixture actor switch is not AD authentication or an ACL evaluator |
| P01-03 / P01-12 | Integrate the qualified transaction profile into the real directory store and journal; preserve receipts/epochs across the actual directory model and recovery formats |
| P01-09 / P01-14 | Package least-privilege local services, provision the real service identity/HBA policy, and implement credential/key custody and rotation before valuable credentials persist |
| P03 / P04 | Domain replication/backup/restore/upgrade and physical host/disk qualification; real-client capacity, soak and independent integrated assessment |

No valuable directory credentials or stable AD storage formats are introduced.
The existing LDAP process is still disconnected from storage/authentication.
The fixed fixture domain/SID and UUID text helper are not AD identity allocation,
DN normalization or Windows conformance. All 60 client conformance scenarios stay
unrun. Accepting P00-15 selects and qualifies this foundational driver/transaction
profile; it does not accept the full server, later phases or production release.
