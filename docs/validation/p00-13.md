## Explicit profile limits and downstream gates

The original criterion is a Phase 0 library/provider/channel **review and
qualification** gate. Each listed part now has a concrete decision, exercised
boundary and recorded limitation. It does not require or accept the unimplemented
LDAP/Kerberos server. LDAPS/StartTLS state, LDAP signing, SASL/GSSAPI, Windows EPA
and RFC 5929 tls-server-end-point remain native integration work (P01-05/P01-16,
SEC-02/SEC-04), with real Windows/Linux/macOS client comparisons. An exporter is
public channel-binding data, not a password, credential, privileged action grant
or replacement for the SASL mechanism. All 60 client conformance cases remain unrun.

The CRL profile is a direct-issuer leaf check using **owned, current, locally
issued synthetic fixtures**. WebPKI's expiry option enforces nextUpdate but its
selected parser does not check thisUpdate. There is no fetched CRL/OCSP, maximum
CRL age, rollback-resistant freshness, intermediate-chain revocation or automated
policy refresh. General external CRL ingestion/production use therefore remains
unqualified; it must not inherit this profile's test result. Revocation applies
to new handshakes, not retroactively to an existing connection's authority.

The key-file permission check is a lab check, not an adversarial production path
resolver, encrypted keystore or HSM. Owner identity, ancestor races, swap/core dump
policy, retained copies/zeroization, hardware/provider lifecycle and protected
operator provisioning need P01-09/P01-14/P01-16 implementation and qualification
before valuable secrets are admitted. The provider fault tests model Rustls API
failure, not physical HSM, OS entropy compromise or malicious clock rollback.
Multi-client load, other CPU/OS builds and independent assessment retain their
normal platform/capacity/P04 gates. No format, SLA, whole phase or production
security acceptance is inferred.
