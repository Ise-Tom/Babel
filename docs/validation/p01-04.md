# P01-04 synthetic LDAP directory reads

The runnable profile is **babel-synthetic-ldap-read-v1**. It serves four
synthetic directory leaves and a naming-context entry over loopback LDAPv3.
The workspace binary **babel-ldap-directory** composes babel-ldap framing,
filter validation, RootDSE and response encoding with the accepted
[babel-synthetic-directory-v1 API](p01-02.md). The existing dependency-free
babel-ldap binary retains its RootDSE profile and separate parser gate.
Ise-Tom owns review. P01-04 remains in progress.

| Base and scope | Expected result |
| --- | --- |
| Empty DN, base | Existing RootDSE projection and matching. |
| DC=babel,DC=test, base | Synthetic naming-context entry with objectClass domain and dc babel. |
| DC=babel,DC=test, one level | Alice, Bob, Readers and Workstation in case-folded CN order. |
| DC=babel,DC=test, subtree | The naming-context entry followed by the four leaves. |
| Existing leaf | Base and subtree select that leaf. One level has no children. |
| Absent leaf or unsupported naming context | noSuchObject (32). A missing direct child returns the known naming context as matchedDN. The reply has no referral URLs. |
| Invalid base in the synthetic DN syntax | invalidDNSyntax (34). |
| Alias dereferencing or unsupported filter operation | unwillingToPerform (53). Malformed filter BER closes the connection. |
| Critical ManageDsaIT or another unknown critical search control | unavailableCriticalExtension (12). Unknown noncritical controls are ignored. |

The adapter creates leaves through Directory::create, resolves base lookups
through lookup_dn and enumerates leaves through entries_by_name. The LDAP
allowlist is objectClass, dc, cn, displayName, uidNumber, dnsHostName and
description where present. Empty selection or '*' reads the public user
attributes, explicit names select their case-insensitive matches, '1.1' alone
returns the DN, and typesOnly returns selected types with empty values.
Requests for objectGUID and objectSid yield no values. The naming context's
dc and objectClass are synthetic adapter attributes. The RootDSE fields
stay the same.

Presence, equality, AND, OR and NOT are supported. Equality of the accepted
core fields delegates to Directory::lookup_equal with the pinned field rules.
The adapter matches objectClass and dc case-insensitively. Unknown fields and
invalid assertion values evaluate as Undefined, including under NOT.
Substrings, ordering, approximate and extensible matches receive refusal
before entries are emitted. The shared parser limits each frame to 16 KiB,
filter depth to 8 and filter nodes to 64. Each connection is bounded by 32
messages and a five-second session budget.

RFC 2696 paging supports sizes 1–4 on directory searches and one active cursor
per connection. An opaque 16-byte cookie is bound to the complete search. A
continuation may change page size. Continuation rotates the cookie, completion
returns an empty cookie, and size zero with the current cookie cancels. Changed,
replayed, cancelled and cross-connection cookies return 53 with no entries.
Page sizes above four return adminLimitExceeded (11). Malformed paging controls
or size zero with an empty cookie return protocolError (2). A nonzero client
size limit caps the whole result across pages and returns sizeLimitExceeded (4)
at the end of a truncated result.

This exercises P00-01 **ldap-directory/search-and-compare** for its Search path,
**ldap-directory/paging**, and the refusal behavior of
**ldap-directory/criticality**. The matrix labels ldap-directory lab-only.
Compare, authenticated session protection, referral continuation, RSAT controls
and licensed cross-target scenarios remain open.

## Reproduce the process probe

On Linux, use the repository's pinned Rust toolchain and hash-locked Python
tooling with ldap3. Run from the root of a clean checkout.

~~~sh
cargo build --locked --release -p babel-ldap -p babel-ldap-directory
python native/babel-ldap/tests/smoke_ldap.py target/release/babel-ldap
python native/babel-ldap-directory/tests/probe_reads.py target/release/babel-ldap-directory \
  --revision "$(git rev-parse HEAD)" --output reports/p01-04-ldap-directory.json
~~~

The [retained local report](../../lab/p01-04-ldap-directory-smoke.json)
binds 40 passing checks to the release binary built at
[the tested source commit](https://github.com/Ise-Tom/Babel/commit/1d3542abd208f0d8c502d3ca2089b38a2da82eca).
The instrumented local probe covered 96.57% of adapter library lines.

The independent ldap3 client runs 40 checks against the actual process. It
verifies RootDSE, fixture reads, attributes, empty results and base, filter,
referral and paging refusals. It sends one malformed version of an ldap3-encoded
SearchRequest and observes connection closure before entries appear. The JSON
retains inputs, decoded replies, outcomes, source/binary hashes and platform and
client versions. It records cookie lengths and excludes cookie values.

Required CI runs the release, instrumented and archive-extracted probes.
It requires 90% adapter library line coverage and fuzzes the directory-control
decoder. The RootDSE smoke and standalone parser qualification stay required.
