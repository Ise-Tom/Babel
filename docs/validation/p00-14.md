Disposition: **Phase 0 dependency-review packet prepared for owner validation**.
Recommend `mit-krb5-1.22.3-linux-x86_64-aes-cts-lab-v1` as the native
Kerberos/PAC *candidate*. This selects a version and a limited build/security

MIT's [1.22.3 release notes](https://web.mit.edu/kerberos/krb5-1.22/krb5-1.22.3.html)
are the current maintenance/advisory baseline. A security update to the selected
series, a PAC validation advisory, upstream EOL, or a changed compiler/crypto
backend invalidates the version decision until source, API and negative tests are
requalified. Track upstream release/advisory channels at least for each dependency
update and before any distributable build. The lab's green result is dated evidence,
not a future advisory guarantee. No custom cipher, checksum or PAC verifier is
approved.

## Exact qualified profile and provenance

The [harness](../../lab/kerberos/run.sh) downloads MIT's signed
`krb5-1.22.3.tar.gz` from
`https://web.mit.edu/kerberos/dist/krb5/1.22/krb5-1.22.3.tar.gz` and rejects
any SHA-256 other than
`fe90af8441ad9fa9b064b8e53077cefb782a96f8a68276b031dc54af1789ff0b`.
Its detached signature must verify under fingerprint
`C4493CB739F4A89F9852CBC20CBA08575F8372DF`, independently matched to the
[MIT distribution page](https://web.mit.edu/kerberos/dist/). The keyserver is an
availability dependency; a retrieved key alone would not establish trust without
the published fingerprint. The build uses upstream `configure` with
`--disable-rpath --without-system-verto --without-libedit`, `make -j2`, and an
isolated temporary prefix. The runner records compiler, make, bison, GPG, curl,
MIT version, probe source/binary hashes and loaded MIT library paths. No system
Kerberos files are edited. `BABEL_KRB5_KEEP=1` is debug-only and retains synthetic
temporary state; normal exit destroys it.

The synthetic `BABEL.TEST` KDC binds loopback port 17889. The only offered ticket
and service-key enctypes are AES-256-CTS-HMAC-SHA1-96 and
AES-128-CTS-HMAC-SHA1-96; the probe records enctypes 18 and 17. RC4, DES and
3DES are absent from this profile. AES-SHA2, cross-realm negotiation, FAST and
PKINIT were not exercised. The service verifier has a service key; the *lab* also
exports a synthetic krbtgt key to test the complete KDC PAC signature path.
Ordinary application services must not receive a production krbtgt key.

The fresh local run on 21 November 2026 used Ubuntu 26.04/WSL2 x86_64 GNU,
GCC 15.2.0, GNU Make 4.4.1, Bison 3.8.2 and GPG 2.4.8. The exact run output and
tool/linkage facts are retained in
[the synthetic local evidence](../../lab/kerberos/evidence/local-wsl-2026-11-21.json).
Required [native CI](../../.github/workflows/native.yml) repeats the signed
source build and probe on Ubuntu 24.04, preserves its JSON artifact and feeds the
native gate. CI on a PR is a separate observation, not a substitute for the local
run or a real Windows client.

## Criterion-by-criterion result

| Criterion | Library behavior observed or reviewed | Babel obligation / limit |
| --- | --- | --- |
| AES | Both synthetic AES-256 and AES-128 tickets passed AP verification and signed PAC checks; `klist -e` shows AES-256 TGT and service ticket, while the second service selects AES-128. | Configure an explicit allowlist for each KDC and service, reject weaker negotiation, rotate keys safely and test real AD clients. Do not infer AES-SHA2 or PKINIT interoperability. |
| PAC verification | `krb5_kdc_verify_ticket` accepted a signed synthetic MIT PAC with service and KDC keys; `krb5_pac_verify` checked client/authtime. A changed PAC byte and mismatched client failed. | Require a non-null PAC where AD authority needs one; validate signature chain, ticket signature, client binding, expected issuer/realm and each required buffer. Parse bounded SID/group/claim data and apply Babel directory ACL and freshness rules. The MIT *minimal* PAC is not an AD logon-info or SID semantics proof. |
| Missing authorization data | `krb5_rd_req` accepted a valid no-PAC AP request; `krb5_kdc_verify_ticket` returned success with **null PAC**. | Explicitly deny PAC-dependent authorization on null, malformed, unsupported or partially verified data. Authentication success cannot itself grant a group, role, delegated or management action. This fail-closed product rule is designed here, not implemented. |
| Service/time/replay | The probe observed wrong-service `KRB5KRB_AP_ERR_NOT_US`, replay `KRB5KRB_AP_ERR_REPEAT` and expiry `KRB5KRB_AP_ERR_TKT_EXPIRED` after a 2-second ticket and 5-second wait. MIT's [`krb5_rd_req` contract](https://web.mit.edu/kerberos/krb5-1.20/doc/appdev/refs/api/krb5_rd_req.html) makes replay-cache behavior conditional on a configured cache. | Use an explicit, persistent, shared replay policy appropriate to service/replica boundaries; refuse cache loss, clock rollback and wrong SPN/audience. The one-process local cache test does not qualify restarts or six DCs. |
| Delegation | MIT's [release notes](https://web.mit.edu/kerberos/krb5-1.22/krb5-1.22.3.html) describe S4U protocol transition/constrained delegation and the requirement for valid incoming PACs. | S4U2Self/S4U2Proxy, forwardable/OK-AS-DELEGATE, allowed target SPNs, transited realms, RBCD/ACL and audit need native policy and negative real-client cases. All delegation execution is **unrun**. Default deny. |
| PKINIT | MIT's [PKINIT documentation](https://web.mit.edu/kerberos/krb5-1.20/doc/admin/pkinit.html) describes certificate/trust-anchor configuration; 1.22 adds EC client certificates/ECDH and Microsoft paChecksum2. | Certificate mapping, trust/revocation, EKU, freshness, account binding and recovery are separate design and client gates. PKINIT is **disabled and unrun** in this profile. Password/keytab AS exchange does not qualify it. |
| Licensing/maintenance | MIT's [full license file](https://web.mit.edu/kerberos/krb5-1.22/doc/mitK5license.html) has MIT and component-specific terms, binary/source notice obligations and export text; this lab retains no redistributed binary. 1.22.3 contains material PAC/security repairs. | Before packaging a product, inventory actual linked objects, full license texts/notices and export obligations; monitor upstream and rebuild/retest on security fixes. Apache-2.0 for Babel does not replace MIT/component notices. |
| FFI/unsafe | The probe uses the public C ABI with owned `krb5_context`, keytab, ticket, PAC, auth contexts and matching free calls. The runtime remains C/native code with its own memory-safety surface; the lab is not a Rust adapter. | Limit future `unsafe` to one audited Rust FFI module with bounded copied inputs, checked lengths/integers, explicit ownership and thread affinity, RAII cleanup, no unwinding across C, no keytab/KDC key in request handlers, sanitized errors and fuzz/sanitizer tests. Reject null PAC and every error before creating an authorized request. |

passed the synthetic local AES, AP-REQ and PAC API tests above. The harness
checks actual return codes, not only diagnostic strings. The signed source,
compile and dynamic-linkage proof bind this observation to the selected C
libraries. The local run is a WSL2 lab and CI is an independent Ubuntu runner.

LDAP/SASL/EPA integration or domain join was exercised. The existing 60
compatibility scenarios remain unrun. Do not map MIT's minimal PAC or a successful
