# P01-13 native DC discovery

The runnable profile is **babel-synthetic-dc-discovery-v1**. It serves
authoritative DNS over loopback UDP for one immutable, synthetic zone,
**discovery.example.test.** Ise-Tom owns review. Requirement acceptance is pending.

## Routes and behavior

| Query or condition | Expected response |
| --- | --- |
| _ldap._tcp.dc._msdcs.discovery.example.test. SRV | The two eligible targets, dc-east and dc-west, with priority 0, weight 0 and port 389 |
| _ldap._tcp.east._sites.dc._msdcs.discovery.example.test. SRV | dc-east only |
| _ldap._tcp.west._sites.dc._msdcs.discovery.example.test. SRV | dc-west only |
| dc-east A/AAAA and dc-west A/AAAA | 192.0.2.10 / 2001:db8::10 and 192.0.2.20 / 2001:db8::20, respectively |
| Stale, ineligible or invalid target; unknown site | NXDOMAIN and an empty answer |
| Supported query type with no records at an existing owner | NOERROR and an empty answer (NODATA) |
| Query outside the zone | REFUSED |
| Unsupported type, class, additional section (including EDNS) or opcode (including UPDATE) | NOTIMP |
| Malformed QUERY or QUERY datagram over 512 bytes | FORMERR when a transaction header is available |

A monotonic clock measures time since service startup. The synthetic live DCs
expire at 300 seconds, and positive TTLs are capped at 30 seconds or remaining
lease time, whichever is lower. The stale fixture expires at startup. The
ineligible fixture is disabled, and the invalid fixture has an unspecified
IPv4 address. Both locator records and direct address lookups use the same
filter. Each locator RRset uses a uniform TTL. Negative answers carry the
synthetic zone's SOA with zero negative-cache TTL. The listener refuses
non-loopback binding. Supported messages have one uncompressed question; it
ignores incoming DNS replies and datagrams too short to read the header.

This executes the scoped DNS SRV and address path of **P00-01
dns-locator/dns-query** and observes the unsupported-update refusal relevant to
**dns-update/secure-update**. The matrix labels dns-locator lab-only. It still
records LDAP ping, legacy discovery and their qualification separately.
[RFC 1035 §§4.1–4.2](https://www.rfc-editor.org/rfc/rfc1035#section-4.1) ·
[RFC 2782](https://www.rfc-editor.org/rfc/rfc2782) ·
[RFC 2308 §3](https://www.rfc-editor.org/rfc/rfc2308#section-3) ·
[PR #47 pinned P00-01 packet](https://github.com/Ise-Tom/Babel/blob/592f83c81126cd5e13bd55de11878160b75a2ce4/docs/validation/p00-01-conformance.md)

## Run the independent probe

On Linux with the repository's pinned Rust toolchain, Python 3.12+ and BIND
dig and nsupdate installed, run from the root of a clean checkout.

~~~sh
cargo test --locked -p babel-dns
cargo test --locked --release -p babel-dns
cargo build --locked --release -p babel-dns
python native/babel-dns/tests/probe_dns.py target/release/babel-dns \
  --revision "$(git rev-parse HEAD)" \
  --output reports/p01-13-dns-discovery.json
~~~

The [retained local transcript](../../lab/p01-13-dns-discovery-smoke.json)
binds all 18 passing exchanges to the compiled
[source commit](https://github.com/Ise-Tom/Babel/commit/2caa31c1f28a2ff3195fa2df6cb3e12fb16b5c19).
The instrumented local run covered 98.12% of DNS library lines.

The probe starts the release service on an ephemeral loopback port and runs
18 BIND exchanges. It records the outgoing queries, incoming responses,
expected and actual results, probe durations, tool and host versions, and
source/binary/lock digests. The UPDATE sends a deletion and replacement for
dc-east's address. nsupdate receives NOTIMP, and a subsequent query returns the
original address. Unit tests also exercise lease expiry at the last valid
second and at the boundary, malformed input, and the packet and name bounds.
Native CI repeats the probe on the release, instrumented and archive-extracted
binaries, requires at least 90% DNS library line coverage, and runs the DNS
datagram sanitizer fuzz target. CI retains probe JSON in native-lab-evidence
and the fuzz log in native-fuzz-evidence.
