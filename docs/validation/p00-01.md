# P00-01 — Protocol operation matrix and ownership

The Phase 0 criterion asks for positive and negative behavior and an accountable
owner for every AD operation in scope, with unknown operations visible.
Ise-Tom approved the scoped matrix design increment on 22 November 2026.
The full P00-01 gate remains open. [Owner review](https://github.com/Ise-Tom/Babel/pull/40#pullrequestreview-6012632874)

## Review the proposal

The [matrix](../../lab/compatibility.json) retains the 30 family IDs, their
requirement and platform scope, their comparison targets, and their original
positive and negative scenarios. It now specifies 60 wire mappings and 12
workflows and records 12 unresolved mappings. Each row inherits its family
owner, Ise-Tom, and names the exchange or control, section references, expected
success, expected refusal and required evidence. Workflows such as cached
Windows logon, Linux service lifecycle and native administration cite the
project contract where the behavior belongs to the OS, deployment or API.

The [reference registry](../../lab/specification-pins.json) binds 153 distinct
section headings to exact publisher editions. DNS discovery and updates use
RFC 1035, 2782, 2136 and 3645 for the wire exchanges. MS-DNSP covers the
separate administration candidate. Kerberos AS/TGS/AP, password change and
S4U use RFC 4120, RFC 3244 and MS-SFU alongside the existing Microsoft
extensions. LDAP paging cites RFC 2696. The [reference-use review](../reference-use-review.md)
describes the allowed use and unresolved rights.

The [conformance evidence](../../lab/conformance-evidence.json) changes only
its matrix SHA-256 binding. All 60 outcomes, reasons, execution lists and
reviews are unchanged. The required family evidence now calls for artifacts
specific to the mapped exchanges, such as LDAP result and before/after state,
RPC method and protection level, client/server authentication correlation, or
a Windows resultant-policy observation. Artifact capture must use disposable
domains and omit credentials, tickets, keys and unredacted payloads.

An unrecognized exchange stays visible under the matrix's unmapped-operation
policy. Record its client/build, interface/opcode/OID, protection, observed
disposition and any state effects, then route it to the accountable owner.
LDAP control handling follows the declared criticality rules. An unresolved
mapping includes the evidence and decision needed before claiming support.

## Reproduce the checks

Run from a clean checkout that preserves committed file bytes. The optional
cache command uses Poppler's `pdftotext` and public publisher files acquired
from the registry into an untracked directory. It checks raw SHA-256 and byte
sizes, along with the operation section headings. A changed publisher edition
requires explicit re-review.

```sh
rev="$(git rev-parse HEAD)"
python scripts/check_conformance.py --revision "$rev"
python scripts/check_state_security.py --revision "$rev" \
  --document-cache /path/to/public-reference-cache
python scripts/check_conformance.py --require-ready
```

Local cache verification checked 21 exact publisher files and all 153 operation
headings. The last command should fail on the current inventory. Required offline CI
retains `protocol-operation-matrix.json` in `phase0-contract-evidence` and
exercises regression cases for missing assertions, broken references, unknown
operations and attempts to qualify unresolved mappings.
