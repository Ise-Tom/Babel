P00-17 gate cannot pass. Any real vulnerability accidentally disclosed during
the drill is handled as a real report, not copied into this public packet.

## Proposed timing decision — **not effective**

The existing [SECURITY.md](../../SECURITY.md) two-contact/tested-route rule
before public previews and the original P00-17 Phase 0 exit remain in force.
The proposal below is an exact policy change for owner review. It must not be
applied or marked accepted merely because this packet or PR passes CI.

**Proposed replacement for the P00-17 row in `docs/phases/phase-00.md`:**

> `P00-17 | Prepare private vulnerability intake and backup response coverage. | A reviewed private-intake runbook and benign offline recordkeeping rehearsal identify reporter/owner/backup roles, custody, acknowledgment, escalation, failure states and a live-drill plan. Phase 0 may accept this process-design evidence only; enabled reporting or simulated receipt is not live receipt or backup coverage. The live private drill and real available backup remain mandatory before supported production under P05-04 and cannot be waived by an unsupported preview.`

**Proposed replacement for the pre-preview and response-target paragraphs in
`SECURITY.md`:**

> `There is no supported production version and no active response SLA. During solo development, a public experimental preview must state that it is unsupported and that only one responder is available. Before soliciting external preview users, the owner must run and privately close a benign live reporting drill that independently verifies owner notification, private receipt and acknowledgment; publish only redacted outcome metadata. If the route fails, do not solicit reports or external testers until repaired. The two-working-day acknowledgment and seven-day update intervals remain proposed targets, not promises.`
>
> `Before any supported production release, appoint two genuinely available security contacts, verify each one's private access and independent receipt/escalation in a benign drill, publish supported-version and coordinated-disclosure policies, complete independent security assessment and rehearse compromise containment, clean recovery and credential/key rotation. Supported response targets require named staffing and evidence that the targets can be met. A shared mailbox, saved draft, bot or untested nominee is not backup coverage.`

This proposal defers the second contact from **before public previews** to
**before supported production**, and moves P00-17's live/backup operational
evidence from a Phase 0 exit to the supported-production P05-04 readiness gate.
It does not relax the live route check before soliciting preview users. If the
owner approves it, the canonical Phase 0 row, `SECURITY.md`, P05-04 linkage,
dashboard and validation plan must be changed in this same branch and reviewed
before any new acceptance is recorded. Until then, use the unchanged rule.

| Milestone if the proposal is approved | Evidence due | Safeguard |
| --- | --- | --- |
| Phase 0 design review | Exact draft, offline case results, custody/escalation runbook, current-route observation, named owner and explicit sole-responder risk | No live/backup claim; original policy remains until merged amendment |
| Before soliciting external preview users | Explicit authorization, live private report ID, reporter confirmation, Ise-Tom's independently observed notification/open/acknowledgment, closure and redacted outcome | Preview visibly unsupported; no active SLA; failed route blocks solicitation |
| Before supported production | Real backup acceptance, least-privilege private access, independent backup receipt and owner-absence escalation, supported-version/disclosure policy, assessment, response and clean-recovery/key-rotation exercises | Release gate fails on missing or stale evidence; no nominal backup or simulated escalation |

The current two-working-day/seven-day text is not a live SLA. A separate owner
decision and operational evidence are required before those targets become a
supported commitment.
