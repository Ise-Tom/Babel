# P00-09 — Workload runner and measurement evidence

The owner approved the [engineering method](../phase-00-workload.md) on
18 November 2026 for the 10,000-user, three-site target. This increment
exercises one Babel interface and supplies measurement evidence for that
profile. Full workload and fault execution remain open. Production SLO
ratification remains an owner decision.

## Executed profile

The `ldap-rootdse-loopback-smoke-v1` profile offered 180 requests at 60/s
over a three-second schedule, with four in flight and 12 outstanding
allowed. A seed determines the position of one expected denial per five
offers. The runner launches the release Babel LDAP binary on an ephemeral
IPv4 loopback port and shuts down the process it owns. Each attempt opens
a new TCP connection and binds anonymously. The success case checks the
`vendorName=Babel` RootDSE entry and LDAP search result 0. The denial case
expects result 53 for a subtree search of RootDSE.

The tooling independently audited the generated fixture before starting the
listener. It contained 165 objects, 508 direct membership edges and 12 nested
edges. The running lab exposes static RootDSE data and has no fixture import.
The dataset seed also controls the operation mix. The negative graph fixtures
were audited for shape, and their protocol denials remain unrun.

## Measurement and replay

Offers derive from absolute monotonic-clock offsets, independent of response
completions. At capacity the runner immediately accounts for a rejected offer.
Each request has a 500 ms deadline measured from its scheduled offer. Queue
time runs from that offer to the start of the TCP connection. End-to-end
latency runs from the offer to the observed terminal outcome and includes
scheduler delay, queue wait, connection, bind and search. For an offer that
never starts, the end-to-end measurement ends at the observed timeout or
admission rejection. Completed counts include validated denials. An unexpected
reply or transport error has its own outcome. The report retains every
terminal outcome in the overall distribution and breaks it down by outcome.
It gives exact nearest-rank percentiles over microsecond samples and inclusive
histogram buckets with a final overflow bucket. This run used one loopback
site, no warmup, a fresh lab process and uncontrolled host cache state.
